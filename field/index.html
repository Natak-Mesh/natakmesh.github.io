Nucleus in the field

Phones join a Nucleus access point and run ATAK over the WiFi mesh at full rate, with no plugin. When a teammate walks out of WiFi range, their position and chat keep moving over LoRa.

The same nodes carry push-to-talk voice, a shared text inbox that plain Meshtastic radios can join, and an internet connection when one node has one. This page covers what each of those does, and where it stops.

01ATAK

ATAK over the WiFi mesh

Connect the phone to the node's access point (0042-nucleus-ap on node 42) and open ATAK. There's nothing else to set up. ATAK finds the other phones on the mesh by itself, with its normal multicast.

Each node forwards ATAK's multicast groups between its access point and the mesh, and the mesh carries them across up to 8 nodes. Positions, chat, pictures, routes and data packages move at WiFi speed, about 30 Mbps between nearby nodes.

Multicast groupATAK traffic
239.2.3.1Position and CoT data (SA)
224.10.10.1Discovery and chat
239.255.255.1, .2, .12ATAK voice plugin: general, presence, channel 1

ATAK sends multicast with a TTL of 1. The node raises it to 8 as it enters the mesh, so it can cross nodes. The mesh drops repeated packets itself, so a busy net doesn't flood.

02LoRa bridge

Position and chat past WiFi range

Every node runs a CoT bridge on its 915 MHz LoRa radio. It picks up ATAK position and chat from the local network, compresses them and sends them over Meshtastic. Nodes that hear them put them back on their own network as normal ATAK multicast. The phone needs no plugin and no setting.

03Voice

Push-to-talk

Voice runs on the node, so any phone on the access point can talk without an app. Open https://0042-nucleus.local/voice, hold TALK and speak. The page needs HTTPS for the microphone. The node uses a self-signed certificate, so the browser asks you to accept it the first time.

Headset

Plug an OpenVLM headset into the node's USB-C port for a hardware PTT button. The node picks it up when you plug it in. Phones and headsets on the same channel hear each other.

How it works

  • 16 kHz audio, multicast over the WiFi mesh.
  • Named channels. The default is 1: Command.
  • No floor control. If two people talk at once, you hear both.
  • The ATAK voice plugin also works, through the multicast groups above.

Optional: speech-to-text over LoRa. The node transcribes a short message, sends it as one Meshtastic packet, and the receiving node reads it out. Off by default. The speech models have to be installed on the node first.

04Text and Meshtastic

One inbox, two radios

The node's Messaging page sends each message over the WiFi mesh and LoRa at the same time. Copies that arrive both ways are merged, and each message shows how it got there: wifi, lora or wifi+lora. Messages are up to 200 characters.

The LoRa copy is a plain Meshtastic text on the primary channel. A Meshtastic radio or phone on the same channel sees your messages, and its messages show up in your inbox.

Join a channel
Ask other Nucleus nodes on the mesh for their channel, then copy it with one tap.
Share a channel
Channel URL or QR code, for any Meshtastic radio.
Radio settings
Name, preset, region, hop limit, TX power and role, from the web UI.
Limit A Meshtastic-only radio reaches the inbox over LoRa only. Nucleus nodes out of its radio range won't see its messages, even when they're on the WiFi mesh.

05TAK server and video

A TAK server on the mesh

Basic ATAK use needs no server. For certificates, data feeds and video, one node can also run a TAK server. Every ATAK client on the mesh or on an access point can reach it.

  • Official TAK Server, with MediaMTX for video. You supply the TAK Server package from tak.gov. A setup script installs it and creates the certificates.
  • OpenTAKServer, installed with its own installer.

A node runs one or the other, never both. Both are off by default, and most nodes never run either.

Default MediaMTX streams are open. Anyone who can reach the node can publish and watch, with no password. Lock it down in its config if that matters to you.

06Internet

Share one connection

Out of the box the Ethernet port is a WAN port. Plug one node into a router, a hotspot or Starlink and it shares that connection with the whole mesh: every node, and every phone on every access point. You don't set anything up on the other nodes.

Without a connection, everything above keeps working. The mesh never needs the internet.
